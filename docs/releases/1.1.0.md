# RestoKit 1.1.0 (2026-11-12)

Replaces 1.0.3 as the live kit. This release also includes the 1.0.4 batch, which was prepared but never published on its own, so 1.1.0 is the next live version after 1.0.3. The previous version stays downloadable for a while.

Live file: `resto_kit_1.1.0.json` (`meta.version` 1.1.0). Sign up for the kit at [resto-kit.com/get-the-kit](https://resto-kit.com/get-the-kit). Agents should check [resto-kit.com/kit/latest.json](https://resto-kit.com/kit/latest.json) on first load in a session.

This page is the public update record and change log for 1.1.0.

## Reorganization

- Seven topics that were in the wrong module were moved to their homes: extension cord safety and temporary power distribution (the spider box and cords) under equipment power; electrical extras under electrical safety; plumbing shutoffs and failure points under source control; dehumidifier ducting under dehumidifier handling; long-dwell sewage handling under crawlspaces; and the HVAC intake ban under HVAC systems.
- Three exact duplicate copies were replaced by short pointers to the one home copy.
- A pointer index was added (`framework_scale.pointer_index`, 489 ids). Every pointer value (`see`, `references`, `source`, `gathered_in`, scope decisions, and other fields that name a place in the kit) is now an id from that index. A whole module uses its module name as its id.
- A pointer id is never shown or spoken to a reader. Agents and the website expand it to the home's full text inline.
- Scope may go past the usual depth limits. That is a declared exception: when scoping, the agent pulls the whole scope object at once, so the extra depth does not slow navigation.
- No field text was reworded except the declared edits listed below.

## 1.0.4 batch (included here)

- The kit does not assume Oregon or any other state. The first time a state-sensitive topic comes up, it asks once "What state do you work in?", remembers the answer, and stays state-neutral until then.
- Oregon and Washington survey examples were moved out of the default rules and are used only when the remembered state matches.
- The Oregon small-repair note is marked as Oregon-only and not a default.
- Short pointers to the jurisdiction rule were added in the related legal, crawlspace, estimating, and sampling sections.

## Billable catalog

Every billable line now lives in one ordered catalog at `main_content.modules.scope.billable_catalog`:

- 117 lines: 97 sheet lines plus 20 company-gap lines (G1–G20), in 10 sections.
- Each line has a label, unit, options, Category 3 mark, stage, notes (inclusions, exclusions, and include-or-never-both rules), origin, and a reason that points to the kit section that explains it. There are no prices.
- The company mitigation sheet is still at its usual template path and is rendered from the catalog at build time. Line numbers are generated at print time from list order; citations are stored as item ids so they always print the current number.
- A company can overlay the catalog with a separate small file: the same item ids, in the company's order, with its own labels, units, and sections. Unmapped lines print in place and are flagged; unknown ids, duplicates, and kit lines left out are flagged.

Sheet cleanup in this release:

- Removed "Use 2x4 for containment" (a 2x4 temporary wall is structural or remodel work, not containment).
- Removed "Check cleaning" (a likely misread from the sheet transcription).
- Dropped the eight blank reserved rows and letter suffixes. Remaining rows are numbered 1–97 with no gaps.
- Added a home for spot pretreatment: treat a heavily soiled or contaminated spot exposed during demo right away, instead of waiting for the full cleaning pass.

## Reader text and style

A declared reader-text pass was applied before publish:

- Em-dash separators in reader text were changed to a colon, comma, semicolon, or parentheses.
- "Gate" stays wherever it names an operational step or stage (for example Job-Type Gate or Final Verification Gate). Elsewhere the wording is "hold" or "check."
- Framework field names and ids stay snake_case. Keys were not renamed.
- Old numbered note bodies were cleaned the same way, and each now ends with the `◇ resto_kit` footer, matching the kit templates.
- Display names use Title Case where they are shown as names. Stage words are plain language.
- The thermal image line is labeled "Thermal (IR) images." The unit is company-decided (per image or per job). Images help find affected areas and back up the moisture map, and are always confirmed with a meter.

Proofread fixes in the same release: "tigh" to "tight"; spacing in "Scoping default:"; the technology versioning line now says 1.1.0; the billable sheet description says G1–G20.
